## 分社计划搜索

电脑与手机点击分社工具栏的搜索图标后，输入学校名称、简称或城市，会在搜索弹窗内实时显示匹配高校。点击结果关闭弹窗，并同步切换地图位置、层级与分社详情；输入框在结果出现时保持原位。无匹配项时显示空结果，Enter 不关闭弹窗；有结果时 Enter 选择首项，方向下键可进入结果列表。手机搜索使用弹窗临时关键词，输入不改变背景地图和列表，退出后清空；电脑保留原有搜索方式。中文输入法组合期间不会误选或清空搜索。

回归命令为 `node scripts/check-branch-search.mjs`，覆盖桌面、手机、横屏、首页与独立分社入口。

手机端玩家计划不显示滚动字，电脑端右侧显示四行交替动字，新增第三行「不当牢玩家／让一切」和第四行「不做 NPC／从此刻发生」，按可用宽高自适应字号。顶部优先活动与更多活动共用 ListingCard，封面在上，下面按状态类型、标题、简介、时间地点组织；优先卡标题略突出，底部信息对齐。活动搜索在弹窗内实时列出名称、类型、状态和时间地点；点击结果或按 Enter 可进入活动，保留搜索前的分类和状态作为返回来源。电脑端保留原搜索方式。回归命令为 `node scripts/check-players-mobile-search.mjs`。

手机端共创广场按项目名、作者、简介及来源实时匹配，在搜索弹窗内直接显示项目结果；点击、方向键和 Enter 可进入项目，保留搜索前的来源和排序以便返回。卡片作者独占一行，标签另起一行；来源与排序按钮保持一排并缩短。电脑端卡片和搜索排版不变。回归命令为 `node scripts/check-plaza-mobile-search.mjs`。

## 玩家空间与返回入口（2026-11-29）

玩家空间以 `view=account` 为入口，参与记录为默认页；`tab=saved`、`liked`、`profile`、`settings` 分别打开收藏、喜欢、玩家资料和账号设置，均可返回参与记录。旧 `view=password` 和 `tab=password` 规范为账号设置。收藏与喜欢按公开项目接口的本人标记读取，参与记录单独读取本人项目、报名及活动名称，切换页面时不混用上一页结果。

手机资料卡的头像、身份、大学和公开联系方式靠左，右侧四个入口分别可点击。手机参与记录的项目项仅展示名称，报名项不显示编号；电脑参与记录保留原有状态与说明。个人资料表单与密码、退出登录表单分开显示。回归为 `node scripts/check-player-space-sections.mjs`，真实注册、点赞收藏、资料保存、改密与会话撤销由 `npm run test:accounts:browser` 验证。

导师、先锋、头号玩家、玩家计划和共创广场栏目首页的返回由 `SiteNavigation.backHref` 提供：电脑放社区导航下方，手机放导航左侧；时光机手机端放影像目录右侧。站内来源继续使用统一返回链，成员入口、商业头像与活动影像入口记录来源，分社成员返回时保留所选学校。活动和项目详情、票根的已有返回位置保持原规则。回归为 `node scripts/check-site-return-actions.mjs`。

我的报名列表仅保留横版 Logo 旁的页面标题，内容区不再重复标题，也不显示指向自身的「我的报名」按钮。列表返回同样位于电脑端社区导航下方、手机端导航左侧，并保留进入来源；无来源时返回玩家计划。社区页面电脑端返回按钮为最小 88 × 48px，高度与顶部账号控件一致；具体票根仍只在底部提供返回。

电脑端玩家资料和账号设置的返回位于各自表单框内右上角，手机端保留框外工具栏返回。手机票根查看页隐藏顶部「我的报名」入口，电脑端保留。

手机玩家计划的「我的报名」为更多活动标题上方的通栏长按钮。筛选栏包含四类活动、状态和搜索，默认状态显示“全部”。参与方式同时存在参与入口与提交作品时，两按钮在手机同一行，电脑保留原摆放。手机分社列表最多显示四行，可继续内部滚动。

手机端搜索统一在搜索框下方显示临时结果，输入不筛选背景内容，也不写入当前地址；关闭、Escape、点空白或选中结果后清空，重新打开为空。玩家计划、共创广场、分社计划共用 `FilterSearch` 的手机临时输入状态；攻略、成员姓名及知识库示例搜索同样清理退出状态。结果直接进入所选活动、项目、章节或成员，保留进入搜索前的页面筛选作为返回来源。电脑端搜索沿用原交互。首页「成立于」使用与玩家计划入口相同的 SpecularButton，深浅主题共用按钮光效。

统一搜索回归为 `node scripts/check-mobile-search-isolation.mjs`；活动和项目的背景不变、空输入重新打开、分类来源和结果跳转由对应手机搜索脚本覆盖。

## 零一玩家计划与零一共创广场（2026-11-16）

零一玩家计划使用 `/players`，零一共创广场使用 `/plaza`。旧的 `?page=players` 和 `?page=plaza` 地址会切换到简短路径，并携带活动、作品或筛选参数。两个页面沿用官网的 SpecularButton、BorderGlow、SiteBackground 和深浅色主题。

- 玩家计划依次展示报名中、进行中、报名截止、已结束的活动。默认前两场优先展示。后台可指定第 1、2、3 位，剩余展示位沿用原排序。状态右侧显示赛事、沙龙或合作。顶部账号按钮左侧提供「我的报名」，卡片列出时间、线上／线下和地点，点击进入票根详情。详情以报名昵称称呼参加者，保留票根撕线与状态，状态图标位于文字左侧；电脑端票根整体放大 20%，底部左侧提供刷新和保存票根、右侧返回，确认时间置于按钮下方。优先活动框与共创广场首排对齐，右侧保留按可用宽高放大的四行交替动字。卡片地点用「线上」或「线下，城市」，详情保留运营填写的地点。活动卡整卡链接到详情，公开分类筛选提供赛事、沙龙和合作。
- 报名中和进行中均可发布关联项目的组队招募；进行中可按运营设置提交作品。已结束场次主要展示审核公开的作品和活动影像入口。招募卡片只显示项目名和最多 30 字的简介，点击打开独立详情，招募表单的返回位于右上角，发布按钮位于底部。活动详情顶部显示通栏海报和区内导航。桌面左侧为标题、标语、介绍与规则，右侧集中状态、时间、地点和参与方式。参与方式作为活动信息的普通字段展示，标签与时间、地点一致；报名已截止时显示纯文字「报名已截止」，比赛显示「参与赛事」，沙龙显示「参与沙龙」。报名中和进行中均可报名，到已设置的报名截止时间或活动结束时间后停止接收。后台选择「官网报名」后在本站填写报名表并取得票根，选择「外部链接」后跳转至运营填写的报名地址。电脑端活动信息和项目信息随详情正文保持固定，较高的信息栏可在自身区域内滚动；手机端正常随页面滚动。
- 广场支持搜索、排序和来源筛选。选择「零一赛事」后可从左侧的「全部赛事」下拉筛选具体活动。未关联零一活动的作品归入「自主投稿」，作品资料中的外部赛事署名仍可查阅。
- 共创广场与玩家计划「更多活动」共用上方通栏封面、下方简介和底部信息的卡片布局。共创广场顶部最多三个项目，优先采用后台置顶设置。下方「更多项目」与「更多活动」桌面每行最多四卡。下方卡片始终占一列，末行保留空位。广场的点赞与收藏按钮可独立操作，点击卡片可进入详情。
- 活动和项目详情使用官网顶栏。活动报名与分享、项目演示／修改／分享分别放在区内导航旁。项目状态与来源并列，活动状态和类型可在信息栏查看。两页的封面满宽，底部渐隐，标题叠放在底边，随正文一起滚动。空间足够时，区内导航吸附在官网顶栏下方。活动作品与广场共用 `/plaza?project=项目ID`。
- 新项目选择「零一赛事」或「自主投稿」。「零一赛事」仅能选择官网已公布、进行中且开放作品提交的场次。从赛事详情进入提交页时预选本场。项目提交后为待审核。管理员可通过或填写原因退回；作者在「我的参与」修改后重新提交。修改公开作品也会重新进入待审核，原赛事关联保留。普通玩家不能执行管理员操作，访客不能读取未公开项目。

### 服务器运行

新增 `server/start.mjs` 提供前端静态文件与 `/api/community/*` API，可在 HTTPS 反向代理后以单进程运行。先执行 `npm run build`，再设置环境变量启动 `npm start`：

- `NODE_ENV=production`：使用 Secure/HttpOnly 会话 Cookie，须通过 HTTPS 访问。
- `COMMUNITY_DATA_FILE`：持久卷上的绝对数据文件路径，与本地示例数据分开；目录应只供服务账号读取。
- `COMMUNITY_ADMIN_EMAIL`、`COMMUNITY_ADMIN_PASSWORD`：首次初始化管理员使用，密码至少 12 位；通过服务器环境配置，不写入仓库。已有数据不会被启动参数覆盖。
- `HOST`、`PORT`：默认 `127.0.0.1:4173`，供反向代理转发。

目前新增互动页面以中文提供，既有官网的语言切换保持可用；首页与菜单的新入口已补齐英文和繁体翻译。

正式模式不加载示例作品、活动或示例账号，且拒绝打开示例数据文件。活动目录由 `COMMUNITY_EVENTS_FILE` 指定的 JSON 数组提供，可参考 `server/community-seed.mjs` 的字段，替换为核实的活动内容并设置 `example: false`。使用稳定、唯一的 ID；状态值为 `open`、`active`、`ended`，`submissionsOpen` 控制作品提交。调整活动后重启服务生效；旧活动 ID 必须保留，避免已有作品来源失效。展示日期为文本。填写明确的开始或结束时间后，已发布活动按时进入相应阶段。未设置开始时间时，由活动组织者手动切换为进行中。

**现有 `deploy/package-release.sh` 仍是静态官网发布流程。只上传 `dist/` 不会运行互动 API。** 上线新功能需使用新增 Node 服务或将 `/api/community/` 反向代理到它，并配置持久数据目录。每个数据目录运行一个社区业务进程。报名使用本机 SQLite WAL 事务，其余业务状态仍由该进程持有，多机写入需要共享事务存储。

### 活动、作品与影像的自动关联规则

- 活动投稿通过 `eventId` 进入统一项目表。审核通过后，玩家计划的「本场作品」与共创广场同时可见，使用同一个项目 ID 和详情页；没有二次复制或独立同步队列。修改后重新待审核时两处同时停止公开，其他活动不会收录此项目。进行中的活动也显示本场公开作品。
- 每场活动第一次进入 `active`（进行中）自动建立一个活动专题，专题 ID 与活动 ID 相同。加载旧数据时为 `active` / `ended` 的活动补建专题；没有开始的 `open` 活动不新建。比赛、沙龙、交流会等活动类型均使用这条规则。
- 重复保存、服务重启、活动改名均不会重建专题；结束后保留作品与照片，重新开启报名也不删除已有影像库。名称、时间和介绍从活动读取，照片通过活动 ID 归属，不通过标题猜测。
- 规则唯一维护在 `server/event-links.mjs`，由持久化提交与启动迁移调用。新增 `albums` 和 `photos` 数据字段，不替换已有账号、项目或报名记录。`GET /api/community/albums` 返回公开专题，`GET /api/community/projects?event=活动ID` 返回该场审核公开作品。
- 管理员在活动详情的「管理活动状态」保存状态，立即触发建库；也可以通过既有 `COMMUNITY_EVENTS_FILE` 配置导入活动。活动可选填 `coverUrl`（公开 HTTP(S) 图片链接），推荐将主体置中。首屏优先卡与更多活动均采用上图下文，详情将图片裁切为横幅。缺图或加载失败时使用品牌底图。配置文件在重启时仍是活动配置来源，使用它时应同步更新状态，避免重启后覆盖后台修改。展示日期不是计时触发器，启动活动以状态变更为准。
- 从影像目录选择分类后直接显示该分类的影像。顶栏分类按钮左侧可在「全部场次」和具体场次之间切换。已有官网现场照片按原图注归入对应历史场次。活动详情的「查看本场影像」可通过 `?page=time-machine&event=活动ID` 直达专题。
- 管理员在专题「添加本场照片」填写图片链接、说明、分类与可选署名。支持 HTTP(S) 图片链接和已存在的 `/images/` 公开素材路径；这不是文件上传接口。添加后公开，禁止普通用户越权、未开始活动添加照片、同专题重复图片链接。没有照片时保留空库，不把已有 28 张历史照片擅自分配给示例比赛。
- 时光机重新进入或窗口恢复焦点时读取最新专题数据。活动、专题和照片元数据由唯一的社区业务进程持久化。
