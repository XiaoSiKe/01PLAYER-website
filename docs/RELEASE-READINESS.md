### 本轮修改

- 活动报名页和详情页在会话请求中取得当前账号在该活动的报名编号。登录玩家打开票根只读该笔记录，「我的报名」只读回执摘要及活动卡片。旧运行时可继续提供原接口数据。
- 报名请求最多等待 15 秒。超时时保留未确认表单和原提交标识，后续可继续确认同一笔报名。数据库故障、旧数据迁移、备份恢复及审核并发由现有集成测试覆盖。
- 官网在解析 HTML 时提早获取公开发布快照，后续应用读取复用同一次传输。首屏按已发布顺序准备照片。延迟和断网时沿用原有超时及默认内容回退，草稿预览继续通过后台鉴权。
- 移除已废弃的单活动置顶桥接入口和旧手机布局探针。修复依赖本机手工数据和旧返回位置的回归脚本，保留正式素材、原件、历史验收和可复跑的测试。

### 性能样本

- Linux x64 容器、正式 Nginx 路由、10,000 条历史报名。100 人从同一地址同时打开活动、提交报名并读取票根，三个阶段各 100/100 完成并逐笔核对了入库。独立 100 人提交样本经 Nginx P95 为 2.11 秒，后台读取第 2 页的 20 条记录用时 91.4 毫秒。容器测试用于验证该组负载和持久化结果。
- 本机 Chrome 比较两个生产构建，禁用缓存，模拟 1.6 Mbps、150 ms 延迟和 CPU 降速四倍。弱网样本须完整下载同一份 112,766 字节的发布快照，渲染已发布照片的标记并准备 16 张照片。初测的约 0.52 秒包含默认内容回退。以完整下载且实际采用发布内容的样本为准。持续回归另核对公开快照在应用入口脚本下载完成前开始请求，且只传输一次。
- 60 篇攻略以 ETag 重验证的 90 次请求全部返回 304，P95 为 1.27 毫秒。

数据库选型与扩容条件见[运营部署](OPERATIONS-ADMIN.md#运行栈与报名存储)。首场活动的报名问卷、时限和审核方式按运营内容核对。

## 性能记录

### 攻略版本检查

本机 Node 24.16.0，同一 60 篇、正文共 3,024,000 字节的有效攻略；顺序发起 100 次带 ETag 的请求，去掉前 10 次，比较其余 90 次。请求经过真实 HTTP 接口，均返回 304。

| 条件请求 | 调整前 | 调整后 |
| --- | --- | --- |
| P50 | 12.57 ms | 0.25 ms |
| P95 | 14.22 ms | 0.72 ms |

响应内容版本在两次测试均为 `9ca07034e33776f02bd30f74dc498a47ea80695c40130b987c2d576374d82f17`。缓存仅保留当前有效快照，不累积历史正文；错误新版本不会退回旧内容冒充成功。

### 报名并发与首页

带 10,000 条历史报名的一次性容器样本：100 人直连提交全部成功，P95 为 443.6 ms；经 Nginx 提交全部成功，P95 为 2109.1 ms。完整的打开活动、提交、读取票根各 100 次均成功，且逐条核对入库。后台第二页 20 条响应为 106.1 ms。容器使用 Docker Linux amd64，在本机 Apple Silicon 上存在模拟开销；这些数据不能推导生产容量上限。

本机 Chrome、1440×900 和 390×900、禁用缓存、1.6 Mbps 下载/150 ms 延迟/CPU 降速四倍的单次冷启动采样：首屏照片准备与预加载释放检查通过，两个视口的帧间隔 P95 均约 16.7 ms；采样窗口最大长任务分别 198 ms 和 208 ms。没有提前请求人脸模型，折叠线下复杂模块保持延迟挂载。此处记录同条件观察，不作所有设备不卡顿的保证。
